## 概述

KBManager 现在是一个 **编辑器 + 管理器** 的桌面工作区：左边是文件目录栏，右边是编辑区，二者在同一块界面里完成「浏览 → 编辑 → 打标签 → 检索 → 同步到 Git」的完整流程。

核心能力：

- ✍️ **内置编辑器**：直接编辑并保存 Markdown，带行号、未保存标记、编码与换行符保持
- 🧩 **VS Code 风格布局**：活动栏（上半切换左侧栏、左下角放工具页）+ 侧边栏（文件 / 检索）+ 多标签编辑区 + 状态栏
- 👁️ **悬浮标签预览**：光标在文件行停留 1 秒，在光标右下角弹出轻量浮层显示全部标签
- 🔍 **按标签检索**：侧边栏切换为检索模式，点结果直接在右侧编辑区打开
- 🗂️ **文件增删改**：右键即可重命名 / 移动 / 删除，资源管理器顶栏可新建，标签随文件迁移
- 🩺 **日志与排错**：左下角「日志」显示本次会话记录与日志文件路径，出错弹窗直接给结论
- 📦 **Git 集成**：Clone、Add、Commit、Push（SSH）

## 快速开始

### 1. 启动应用

双击 `KBManager.GUI.exe`，窗口居中显示，默认为「文件」侧边栏 + 空编辑区。

### 2. 首次配置

点击最左侧活动栏的 **设置**，填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| Git 用户名 | 用于 Git 提交记录 | `Zhang San` |
| Git 邮箱 | 用于 Git 提交记录 | `zhangsan@example.com` |
| 仓库目录 | 本地知识库的根目录 | `D:\MyKB` |

远程地址（HTTPS / SSH）可选填，用于 Clone 和 Push。点击 **保存配置**。

### 3. 建立索引

点击活动栏的 **文件**，再点资源管理器顶栏的 **同步**。首次会自动创建索引数据库，并扫描入库仓库里所有 Markdown 文件。

> 💡 索引数据库位于 `<仓库目录>/.kbdatabase/KbInfo.db`，随仓库一起迁移。

### 4. 打开并编辑

在文件树中**单击**任意文件即可在右侧编辑区**预览**（标签标题为斜体），**双击**则固定打开；直接点进正文编辑也会自动转为固定打开。改完按 `Ctrl+S` 保存。

### 5. 打标签与检索

在正文上方标签条右侧的输入框输入标签并回车；之后点击活动栏的 **检索**，输入标签名即可反查所有使用该标签的文件。

```

│    │ │ 按文件名过滤… │ │ 架构 ✕ 编辑器 ✕ 重构 ✕    添加标签… [添加]  │ ← 标签条（只有一行）
│ 检 │ └───────────────┘ ├────┬────────────────────────────────────────┤

│    │    2024-05-01.md1 │  2 │                                      │

│    │    architecture 8 │    │ 长段落自动折行显示，行号留在左边不动。 │
│    │    refactoring  3 │  4 │                                      │

│    │    avalonia-note 2│    │                                      │

│ ───┤                   ├────┴────────────────────────────────────────┤
│ 设置│                   │ 行 3 列 8 共 13 行 UTF-8 LF                  │ ← 文档状态条
```

窗口顶部**没有应用自绘的横栏**：标题栏由系统提供，仓库路径与最近一条状态消息都放在底部状态栏里。
编辑区从上到下只有三行「框」——标签页（26px）、标签条、文档状态条——每一行都是固定高度，剩下的全给正文。

### 活动栏为什么分两组

活动栏的图标按「点了以后发生什么」分成两组，这样逻辑是一致的：

| 分组 | 位置 | 行为 |
|------|------|------|
| **文件 / 检索** | 上半部分 | 切换**左侧栏**显示哪个面板，编辑区不变 |
| **设置 / 日志 / Git** | **左下角**（与上半部分有分隔线） | 在**编辑区**打开一个标签页，占满整个宽度 |

把设置类工具放在左下角，和 VS Code 把设置、账户放在左下角是同一个思路：它们是「工具页」而不是「浏览视图」，需要完整宽度，也不该和浏览视图抢左侧栏。

| 区域 | 说明 |
|------|------|
| **活动栏** | 最左侧竖条；当前项左侧有高亮条 |
| **侧边栏** | 显示「资源管理器」或「检索」，与编辑区之间可拖动分隔条调整宽度 |
| **文档标签页** | 每个打开的文件一个标签，**等宽固定宽度**；`●` 表示未保存，`✕` 关闭；标签标题为**斜体**时表示这只是「预览」标签（见下一节） |
| **编辑区** | 一行标签条（左标签、右添加）+ 常驻行号栏与正文 + 文档状态条（只显示信息，没有按钮） |
| **状态栏** | 仓库路径、已索引文件数、标签数、最近一条状态消息、当前文档路径 |

### 预览标签与固定标签

打开文件时有两种「打开」，和 VS Code 一致：

| 操作 | 结果 |
|------|------|
| 在文件树里**单击**文件 | 预览：只占用**一个**预览标签（标题斜体），下一次单击会替换它，浏览文件不会堆积一堆标签 |
| 在文件树里**双击**文件、按**回车**、或从**检索结果**打开 | 固定打开：标签标题转为正体，不会被替换 |
| 点进正文开始编辑（或在预览标签里点一下正文区） | 自动转为固定打开 |
| 单击已经在预览中的文件 | 仍然只是预览（不会重复打开，也不会降级已固定的标签） |

> 💡 预览标签的位置是固定的：下一次预览会替换它的内容，而不是新开一个标签。所以在文件树里上下点选时，编辑区不会越点越多。

## 资源管理器（文件）

点击活动栏 **文件** 进入。这一栏刻意做得紧凑，行高、缩进和徽标位置都对齐 VS Code 的资源管理器。

### 顶部区域

| 控件 | 作用 |
|------|------|
| **共 N 个文件** | 当前索引中的 Markdown 文件总数（有过滤时显示的是过滤后的数量） |
| **新建** | 新建 Markdown 文件，输入相对仓库根的路径（不带扩展名会自动补 `.md`） |
| **同步** | 扫描仓库，把新增的 Markdown 文件补进索引 |
| **折叠** | 折叠所有目录（等同 VS Code 的 Collapse Folders in Explorer） |
| **按文件名过滤…** | 按路径子串实时过滤文件树；输入后目录会自动展开，右侧 `✕` 清除过滤 |

### 文件树交互（对照 VS Code）

| 操作 | 行为 |
|------|------|
| 单击文件 | **预览**该文件（斜体标签，下一次单击替换它） |
| 单击目录 | 选中该行（展开 / 折叠请点箭头，或双击） |
| 双击 / 回车 | **固定打开**文件；对目录则是展开 / 折叠 |
| 右键 | 弹出菜单，作用于**被右键的那一行**（不需要先选中）：打开、用外部程序打开、**打开所在目录**、重命名 / 移动、删除；目录只有「打开」 |
| ↑ / ↓ | 在可见行之间移动选中项 |
| → / ← | 展开 / 折叠目录 |
| 悬浮 1 秒 | 在**光标右下角**弹出标签预览浮层 |

> 💡 编辑区里当前显示的文件，在树里会**同步高亮**（并把所在目录展开），所以从标签页回到目录栏时，总能一眼看到它在哪里。

### 每行显示什么

- **目录**：左侧是展开箭头，名称后面右对齐显示其下的 Markdown 文件数（灰色小字）
- **文件**：名称后面右对齐显示标签数量徽标（浅蓝小圆角标签）；没有标签时不显示徽标
- 名称过长会以省略号截断，不会换行，因此每一行高度固定、扫读很快

### 目录树以磁盘为准

这一栏**枚举真实目录**来构建，索引（数据库）只负责提供标签。所以：

- 在 KBManager 之外删除或重命名的文件，**不会**继续出现在树里
- 在 KBManager 之外新增的 Markdown 文件，重新加载后会直接出现（想让它可以被打标签，点一下 **同步** 入库即可）
- 如果索引里还留着「磁盘上已经不存在」的记录，树里不会显示它们，而是在**底部**给出提示：

  > 索引里有 N 条记录，其文件已不在磁盘上　[查看并清理…]

  侧边栏这里**只放一行计数 + 一个按钮**：失效记录可能很多，铺在目录栏里会挤掉文件树。
  点 **查看并清理…** 会在**右侧编辑区新开一个标签页**（见 [清理失效记录](#清理失效记录页)），
  在那里看完整列表并决定是否清理。把鼠标停在提示上会有一份简短说明，因为这块面板贴在窗口底部，
  浮层是**向上弹出**的，不会被窗口下沿挤成空框。

### 新建 / 重命名 / 删除的行为

- **新建**：只接受 Markdown 扩展名（`.md` `.markdown` `.mdown` `.mkd` `.mkdn` `.mdwn`）；未写扩展名自动补 `.md`。创建后会自动入库并立即在编辑区打开
- **重命名 / 移动**：输入新的相对路径即可移动文件（父目录会自动创建）；目标已存在时**默认拒绝覆盖**，不会静默丢数据；已打开的文档会跟随移动到新路径，标签保持不变
- **删除**：先移除索引记录，再删除磁盘文件；如果磁盘删除失败（例如文件被占用），会明确提示「索引记录已移除，但磁盘删除失败」

> ⚠️ 删除是不可撤销的，也没有回收站。误删只能靠 Git 恢复。

## 清理失效记录页

路径：资源管理器底部 **查看并清理…**（只在存在失效记录时出现）→ 在编辑区新开一个标签页。

索引（数据库）里的记录可能比磁盘上的文件多——比如你在 KBManager 之外删掉或重命名了文件，
`同步` 又只补新文件、不会自动删记录。这些"失效记录"不会出现在文件树里，但需要你决定怎么处理，
所以单独给了这一页：

| 区域 | 说明 |
|------|------|
| 顶部说明 | 解释这些路径为什么在索引里、却不在磁盘上；并说明这一页不会改动磁盘文件 |
| 摘要 | 共多少条失效记录、当前仓库路径；右上角 **重新检查** 可重新扫描 |
| 列表 | **全部**失效记录的相对路径，等宽字体逐条列出；条目多时可滚动，路径过长会省略号截断，悬停可看完整路径 |
| 底部 | 左侧一行说明"清理只会删除索引记录与关联标签，磁盘文件不动，点击后还会再确认一次"；右侧是决定按钮 **清理这 N 条记录**（没有失效记录时该按钮为禁用状态） |

点底部按钮后：

1. 弹出确认框，写明将移除多少条记录；
2. 逐条删除索引记录，不再被使用的标签会被自动回收；
3. 完成后自动重新检查一次，并刷新资源管理器与状态栏计数。

> ⚠️ 清理**不会**删除磁盘上的文件，只删索引记录和标签；但被删掉的标签无法自动恢复，需要重新打。

## 悬浮标签预览

把光标停在任意**文件行**上满 1 秒，就会在**光标右下角**弹出一个轻量浮层，显示：

- 文件名（加粗）
- 该文件已有的**全部标签**，以芯片形式换行排列
- 如果该文件还没有标签，会明确显示「暂无标签」

浮层贴着光标出现，鼠标移开即消失，不会遮挡你正在看的那一行。整个浮层只有一层边框（不再有内外两层），内容上只保留文件名与标签，不再显示路径。

> 💡 延迟是 1 秒，正常上下扫读文件列表时不会被频繁打扰；只有真正停下来看某个文件时才会弹出。浮层很轻（小字号 + 细边框 + 柔和投影），不会像大块面板那样突兀。

## 编辑器

在文件树里单击文件预览、双击固定打开，或从检索结果点击，都会在右侧编辑区打开一个文档标签页。

### 标签条（只有一行）

编辑区最上面只有**一行**：左边是当前文档已有的标签，最右边是添加标签的输入框与 **添加** 按钮。
标签多的时候这一行会**横向滚动**，而不是换行堆高，所以正文永远不会被标签挤下去。

### 正文区

- 左侧是**行号栏**：常驻显示，横向不滚动，纵向与正文一起滚动，因此永远看得见
- 正文**自动折行（软换行）**：长段落按窗口宽度折成多行显示，阅读长段落不用左右拖
  - 折行只是**显示**上的换行，缓冲区里仍然是同一行；保存时不会写入硬换行
  - 一个逻辑行折成多行时，行号只出现在它的第一行，续行留空（和 VS Code 的折行显示一致）
- 因此编辑区**没有横向滚动条**：既不需要，也保证了行号栏不会被滑走
- 支持 `Ctrl+Z` / `Ctrl+Y`（TextBox 自带撤销重做）

### 文档状态条

一条 26px 的行，只显示信息，**没有任何按钮**：`行 N`、`列 N`、`共 N 行`、`N 字符`、编码（`UTF-8` 或 `UTF-8 BOM`）、
换行符（`LF` 或 `CRLF`）、未保存标记（`未保存 · Ctrl+S 保存`）、编码警告，以及最近一次操作的结果（保存、打标签等）。

### 怎么保存

**`Ctrl+S`**（或关闭标签时在弹窗里选「保存」）。保存按钮已经去掉：

- 有未保存修改时，标签上出现 `●`，文档状态条出现 `未保存 · Ctrl+S 保存`，提示足够醒目
- **`Ctrl+R`** 重新从磁盘读取（有未保存修改时会先确认），相当于原来的「重新加载」按钮

### 保存时会发生什么

1. 按文件**原有的换行符**（LF / CRLF）与 **BOM 设置**写回，不会「打开一下就把整个文件重写成 LF」
2. 先写同目录临时文件再替换，中途失败不会留下写了一半的笔记
3. 如果该文件还没有索引记录，会顺手补上，之后就能直接打标签

### 关闭文档

点标签上的 `✕` 或按 `Ctrl+W`。如果存在未保存修改，会弹出三选一对话框：

- **保存**：保存后关闭（保存失败则取消关闭）
- **不保存**：丢弃修改直接关闭
- **取消**：什么都不做，回到编辑状态

## 标签编辑

标签条位于编辑器正文上方（**只有一行**），管理**当前文档**的标签：

- **左侧**：现有标签以芯片展示，点芯片上的 `✕` 立即移除；没有标签时显示「暂无标签」
- **右侧**：在输入框输入标签名：
  - 输入即出现候选列表（浮层覆盖在正文上方，不会把正文挤下去），候选按「被多少文件使用」降序排列，只显示当前文件**尚未拥有**的标签
  - **单击候选**直接添加
  - **回车**提交输入框里的标签名（新标签也可以直接创建）
  - 也可以点 **添加** 按钮
- 最近一次操作的结果显示在**文档状态条**上（例如「已添加标签 xxx」）

> 💡 一个文件可以挂任意数量标签；标签与文件是多对多关系。当某个标签不再被任何文件使用时，会被自动回收。

## 检索（按标签）

点击活动栏 **检索** 进入。

1. **聚焦搜索框**：列出仓库中的**全部标签**，按文件数降序，形如 `重构  (3 个文件)`
2. **输入关键词**：实时模糊过滤（不区分大小写，包含匹配）
3. **点击候选**：填入标签名并立即检索
4. **回车** 或点 **检索**：手动检索
5. **清空**：清空输入与结果

### 结果列表

每个结果是**一整行可点击的按钮**，点击即在右侧编辑区打开该文件。每行显示：

- 文件名
- 所在目录（灰色）
- 该文件的**全部标签**（而不只是匹配到的那个）

底部会显示统计，例如 `标签「重构」匹配 1 个文件`；没有匹配时显示 `没有文件使用标签「xxx」`。

### 索引里有、磁盘上没有的文件

标签只存在于索引里，所以可能出现「索引里有这条记录，但文件已经被删掉了」。这种情况**不会把结果藏起来**，而是：

- 该行的文件名下方用红色标注 **磁盘上已不存在（索引记录失效）**
- 该行**不可点击打开**（避免点开才报错），并多出一个 **移除记录** 按钮
- 统计里会写明，例如 `标签「重构」匹配 3 个文件，其中 1 个在磁盘上已不存在`

点 **移除记录** 会二次确认后只清理这一条索引记录（磁盘文件不受影响）。想一次看清并清理全部失效记录，用资源管理器底部的 **查看并清理…** 打开 [清理失效记录页](#清理失效记录页)。

## Git 操作

点击活动栏 **Git**，在编辑区标签页中打开。打开时会自动在日志区显示当前配置。

| 按钮 | 功能 |
|------|------|
| **Clone** | 克隆远程仓库（优先 SSH，失败回落 HTTPS），并初始化子模块 |
| **Main Add** | 暂存主仓库变更（跳过子模块内部文件，只记录子模块指针） |
| **Sub Add** | 暂存所有子模块内的变更 |
| **查看配置** | 在日志区显示用户名、邮箱、远程地址与本地目录 |
| **Main Commit** | 用下方提交信息提交主仓库 |
| **Sub Commit** | 提交所有子模块，提交信息自动追加 `[submodule: <name>]` |
| **Push (SSH)** | 先推送子模块，再推送主仓库；推送前会二次确认 |

- 所有操作在后台线程执行，界面不会卡住
- 日志带时间戳，自动只保留最近的内容
- 自动探测 `~/.ssh/id_ed25519`，回落到 `~/.ssh/id_rsa`
- GUI 下不会弹出控制台输入提示：找不到密钥会直接报错，而不是卡住

## 日志与排错

点击**左下角**活动栏的 **日志**，在编辑区打开日志页。

### 日志页内容

| 元素 | 说明 |
|------|------|
| **日志文件路径** | 当前正在写入的日志文件绝对路径 |
| **本次会话记录** | 本次启动记录了多少条错误（没有错误时显示「本次会话没有记录到错误」） |
| **刷新** | 重新读取内存中的最新记录 |
| **复制** | 把整份日志复制到剪贴板，方便贴到 issue 里 |
| **打开日志文件** | 用系统默认程序打开日志文件（可直接看到历史会话） |
| **日志正文** | 带时间戳与级别的记录，深色面板显示 |

### 日志都记录了什么

- 启动信息（版本、操作系统、.NET 版本）
- 生效中的仓库目录、以及仓库目录是否存在
- 索引就绪状态（文件数 / 标签数）
- 每次打开文件：相对路径、成功后的行数与字符数；失败时的原因
- 文件的新建 / 重命名 / 移动 / 删除结果
- Git 面板的每一步操作输出
- 未处理异常与未观察的 Task 异常（同时写入桌面的 `KBManager_crash.log`）

### 日志文件在哪

1. 优先写在**程序目录**下的 `logs/kbm-<日期>.log`
2. 如果程序目录不可写（例如装在 `Program Files`），回落到 `%LOCALAPPDATA%\KBManager\logs`
3. 具体路径以日志页顶部显示的为准

### 打开文件失败时怎么排查

弹窗会直接给出可操作的结论。最常见的是这两种：

1. **「文件不在磁盘上：…」** — 索引里的记录过期了（文件在 KBManager 之外被移动、重命名或删除）。
   → 点资源管理器标题栏的 **同步** 刷新索引；若整棵树都不对，检查 **设置** 里的仓库目录。
2. **「无法读取 …」** — 文件存在但读不出来（权限、被独占占用、编码异常等）。
   → 弹窗与日志里会带上具体原因；把日志页内容复制出来即可定位。

## 主题自定义

KBManager 通过 `theme.json` 自定义全局配色。

### 文件位置

放在 `KBManager.GUI.exe` 同级目录下；不存在时首次运行会自动生成一份带注释的样例。

### 自定义方式

编辑 `theme.json` 里的颜色值（支持 `#RRGGBB`、`#AARRGGBB` 或 `Transparent`），共 **64 个语义化颜色标记**，分为以下类别：

| 类别 | 标记示例 | 说明 |
|------|---------|------|
| **品牌色** | `PrimaryColor`, `PrimaryHoverColor` | 主色调：主按钮、标签数、聚焦边框 |
| **危险色** | `DangerColor`, `DangerHoverColor` | 删除、危险操作 |
| **次要色** | `SecondaryColor`, `SecondaryHoverColor` | 次要按钮 |
| **文字色** | `TextPrimaryColor`, `TextMutedColor`, `TextLinkColor` | 各级文字、标签芯片文字 |
| **背景色** | `BackgroundSidebarColor`, `BackgroundChipColor`, `BackgroundDarkColor` | 侧边栏、芯片、日志区 |
| **边框色** | `BorderDefaultColor`, `BorderFocusColor` | 边框、分隔线、聚焦态 |
| **活动栏** | `ActivityBarBackgroundColor`, `AccentBarColor` | 最左侧竖条与当前项高亮条 |
| **编辑器** | `EditorBackgroundColor`, `EditorGutterBackgroundColor`, `EditorLineNumberColor`, `EditorSelectionColor` | 正文区、行号栏、选区 |
| **文档标签页** | `TabActiveBackgroundColor`, `TabInactiveForegroundColor`, `TabDirtyIndicatorColor` | 标签页与未保存圆点 |
| **工具栏 / 状态栏** | `ToolbarBackgroundColor`, `BackgroundStatusBarColor` | 工具栏与底部状态栏 |
| **浮层** | `PopupBackgroundColor`, `PopupBorderColor` | 悬浮标签预览浮层 |

修改后重新启动应用即可生效。文件支持 JSON 注释（`//`）。

| 内容 | 位置 |
|------|------|
| 应用配置 | Windows：`%APPDATA%\KBManager\config.json`；Linux：`~/.config/KBManager/config.json` |

## 常见问题

### Q: 文件树是空的 / 看不到我刚放进仓库的文件？

A: 文件树是**枚举真实目录**得到的，所以只要文件是 Markdown 就会显示。如果整棵树都空，多半是「设置」里的仓库目录不对，或者该目录下确实没有 Markdown 文件。新放进来的文件想让它能被打标签，点一下 **同步** 把它写进索引即可。

### Q: 我删掉的文件为什么还在？（或：搜索里出现了不存在的文件）

A: 删除索引记录不会自动发生——`同步` 只补新文件。目录树以磁盘为准，所以已删除的文件**不会**再出现在树里；如果索引里还留着这条记录，资源管理器底部会提示「索引里有 N 条记录，其文件已不在磁盘上」，点 **查看并清理…** 会在编辑区打开 [清理失效记录页](#清理失效记录页)，那里列出全部条目、底部按钮决定是否清理；按标签检索时这类记录也会被红色标注、禁用打开，旁边有 **移除记录** 按钮。

### Q: 单击文件只是斜体标签，是没打开吗？

A: 那是**预览**模式（和 VS Code 一样）：单击用于快速翻看，只占用一个预览标签，下一次单击会替换它；**双击**（或回车、或从检索结果打开、或直接在正文里编辑）就会变成固定标签，标题恢复正体。这样在目录里连续点选文件时不会堆出一排标签。

### Q: 行号为什么会跟着横向滑动跑掉？

A: 以前不会折行，正文可以横向滚动，行号栏和正文在同一个横向滚动区里，所以往右拖就看不到行号了。现在正文改为**软换行**、编辑区不再横向滚动，行号栏在滚动轴之外，**永远停在左边**；折成长行的部分，续行留空行号（一个逻辑行只编一个号）。

### Q: 自动折行会不会把文件内容改掉？

A: 不会。折行是**显示**行为，缓冲区里仍是同一行，保存时不会写入硬换行（换行符仍按文件原有的 LF / CRLF 写回）。

### Q: 侧边栏/编辑区的滚动条太碍事，会挡住内容？

A: 滚动条在不使用时完全隐藏，鼠标靠近时才露出一条细线，**不会因为悬停而变粗**，因此不会盖住最后一行文件或抢走点击。

竖条的**上下两端**曾经有一段到不了的"死区"：Fluent 在滚动条两端各放了一个默认不可见的翻页箭头，它们虽然看不见却占着高度，于是滑块被顶掉一截，看起来像边界不对。现在这两个部件已从布局中移除，轨道占满整条，**滑块行程与实际内容范围一致**，滑到顶/底就真的到两端。

横向：资源管理器的目录树与检索结果列表**不横向滚动**（过长的文件名用省略号截断，完整信息可以看悬浮预览，侧边栏本身也能拖动变宽）。编辑器正文改为**软换行**后也不需要横向滚动，所以行号栏永远停在左边。

### Q: 重命名 / 删除按钮在哪？

A: 在文件行上**右键**。这两类操作放在右键菜单里（和 VS Code 一致），资源管理器顶栏只保留新建 / 同步 / 折叠。单击行是**预览**，双击才是固定打开，回车同样固定打开。

### Q: 为什么搜索不到结果？

A: 需要先有文件被索引，并且该文件带有对应标签。先去 **文件** 里点 **同步**，再给文件打标签。

### Q: 标签候选列表是空的？

A: 需要先为一些文件添加标签；候选来自已有标签的汇总。新标签可以直接输入后回车创建。

### Q: 悬浮一秒没有弹出标签浮层？

A: 确认鼠标停在该行**没有移动**满 1 秒；浮层只在文件（而非目录）上显示标签。浮层出现在光标的右下角，鼠标移开即消失。

### Q: 提示「打开失败」，我怎么知道原因？

A: 弹窗会写明结论（例如「文件不在磁盘上」，通常是索引过期）并附上日志文件路径。也可以点左下角的 **日志**，那里有本次会话的完整记录、日志文件路径，以及「复制」「打开日志文件」按钮。详见 [日志与排错](#日志与排错)。

### Q: 右下角的「打开日志文件」点了没反应？

A: 如果日志文件还没创建（本次会话尚未写入任何内容），会提示「日志文件尚未创建」；正常情况下会用系统默认程序打开。也可以直接在日志页里选中文本复制。

### Q: 保存后 Git diff 整篇都变了？

A: 正常情况不会。保存时会保留原文件的换行符与 BOM。如果你之前用别的工具把文件改成了统一换行符，第一次保存会按文件原来的主导换行符写回，之后 diff 就稳定了。如果文档状态条出现**编码警告**，说明原文件不是有效 UTF-8，保存前请先确认内容。

### Q: 关闭标签页时点了「不保存」，修改还能找回吗？

A: 不能。请用 **保存** 或 **取消**。编辑器目前不保留临时副本。

### Q: 删除了文件还能恢复吗？

A: 不能撤销，也没有回收站。如果仓库是 Git 仓库，可以用 `git checkout` 恢复。

### Q: 提示「文件不是有效的 UTF-8」怎么办？

A: 该文件可能是 GBK 等非 UTF-8 编码。应用会宽松解码并给出警告，界面里可能显示替代字符。建议先用别的工具转成 UTF-8，再在 KBManager 中编辑保存。

### Q: 按钮都是灰色的点不了？

A: 通常是还没有配置仓库目录（去左下角 **设置** 填好并保存）；文件树为空时也不会有可操作的行。重命名 / 删除等文件操作在行的**右键菜单**里。

### Q: Push 失败？

A: 请确认：

1. 设置中已配置 SSH 远程地址
2. `~/.ssh/` 下存在 `id_ed25519` 或 `id_rsa` 密钥
3. 已把 SSH 公钥添加到远程仓库

### Q: 应用闪退怎么办？

A: 桌面会自动生成 `KBManager_crash.log` 崩溃日志文件，可据此排查。

### Q: 如何更换配色？

A: 编辑应用目录下的 `theme.json`，修改颜色值后重启即可。详见 [主题自定义](#主题自定义)。
